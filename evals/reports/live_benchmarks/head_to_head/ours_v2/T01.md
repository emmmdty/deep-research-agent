## Executive Summary

- LLM-based agents have become central to AI research and applications, with evaluation, memory, planning, and tool use identified as core components of agent architectures.
- Multiple frameworks (ReAct, Reflexion, AutoGPT, BabyAGI, MetaGPT) and benchmarks (AgentBench, WebArena, SWE-bench) have been developed to advance agent capabilities and assessment.
- Memory is a critical but often under-analyzed component of agent systems, with human memory types (sensory, short-term, long-term) informing agent memory design.
- Industry guidance from OpenAI, Anthropic, Google, and Meta emphasizes practical patterns for building effective agents, including single-agent vs. multi-agent architectures and tool integration.
- Agent evaluation is more complex than evaluating LLMs in isolation due to dynamic environments, tool use, and interactive behaviors, with enterprise-specific challenges (security, reliability, compliance) often overlooked.

## Findings

### 1. LLM Agents: Core Components and Architectures

LLM-powered autonomous agent systems consist of planning, memory, and tool use components (critical). Planning involves subgoal decomposition and self-reflection (critical). Memory is divided into short-term and long-term types (critical). Tool use enables agents to call external APIs for information missing from model weights (critical).

Agent architectures are either comprised of a single agent or multiple agents working together (critical). Single agent architectures are powered by one language model performing all reasoning, planning, and tool execution (critical), and excel when problems are well-defined and feedback from other agents or users is not needed (critical). Multi-agent architectures involve two or more agents, each potentially using the same or different language models (critical), and tend to thrive when collaboration and multiple distinct execution paths are required (critical). Multi-agent architectures are divided into vertical (leader-based with clear division of labor) and horizontal (all agents equal, shared discussion thread) categories (critical).

Notable single agent methods include ReAct, RAISE, Reflexion, AutoGPT + P, and LATS (critical). Each of these methods contains a dedicated stage for reasoning about the problem before any action is taken (accepted, non-critical).

### 2. Key Agent Frameworks and Methods

**ReAct** (Reason + Act) enables AI agents to solve complex tasks by combining logical reasoning with tool usage like web searches or code execution (critical). ReAct integrates reasoning and acting by combining task-specific actions and language space (critical), and works better than an Act-only baseline on knowledge-intensive and decision-making tasks (critical). ReAct is a foundational work on synergizing reasoning and acting in language models (critical, arXiv:2210.03629).

**Reflexion** is a language agent framework using verbal reinforcement (critical), equipping agents with dynamic memory and self-reflection capabilities to improve reasoning (critical). Reflexion uses a heuristic function to detect inefficient planning or hallucination (critical), and after each attempt, has the agent critique its own output and retry with that critique in memory (accepted). Reflexion improved HumanEval coding pass rates from 80% to 91% (accepted), but is expensive because every retry is a full run (accepted). Reflexion uses metrics such as success state, current trajectory, and persistent memory, with an LLM evaluator providing specific feedback (accepted). Reflexion results in improved success rate and reduced hallucination compared to Chain-of-Thought and ReAct (accepted).

**AutoGPT** is modular and extensible, suited for developers needing customizable agents able to handle complex task decomposition, memory management, and integrations with tools and APIs (critical). AutoGPT is best for advanced automation and workflow orchestration (critical), and provides a feature-rich framework for goal decomposition, tool integration and external API use (critical).

**BabyAGI** is an autonomous agent framework that generates and runs a sequence of tasks based on a user-provided objective (critical). BabyAGI orchestrates a loop of task creation, execution, and prioritization using an LLM and a vector memory store (critical). BabyAGI's architecture sets up three dedicated 'agents' (all powered by the same GPT-4): one to execute tasks, one to create new tasks, and one to prioritize the task list (critical). BabyAGI is simple, minimal, and focused on a single iterative task loop, good for rapid prototyping and educational exploration (critical). BabyAGI is more of an educational sandbox as opposed to a production-grade application (critical). BabyAGI is less prone to the 'wandering' failure mode that plagues AutoGPT (critical), and researchers, system designers, and educators consistently rate BabyAGI higher than AutoGPT for interpretability and structured task decomposition (critical).

**MetaGPT** is a multi-agent framework that enables GPT to work in a software company, collaborating to tackle more complex tasks (critical). MetaGPT assigns different roles to GPTs to form a collaborative entity (critical), simulating an entire software company using specialized agents that interact based on standard operating procedures and an assembly-line paradigm (critical). MetaGPT includes agents acting as product managers, architects, project managers, and engineers (critical). MetaGPT encodes SOPs into prompt sequences to organize and promote multiagent workflows (critical), and uses structured outputs to reduce the risk of hallucination caused by idle chatter between LLMs (critical). The MetaGPT paper was published on Jan. 16, 2024 (critical).

### 3. Memory in Agent Systems

Memory is a core component of LLM-powered autonomous agents, defined as the processes used to acquire, store, retain, and later retrieve information (critical). Human memory types include Sensory Memory, Short-Term Memory (STM) or Working Memory, and Long-Term Memory (LTM) (critical). Sensory memory typically lasts up to a few seconds, with subcategories including iconic (visual), echoic (auditory), and haptic (touch) memory (accepted). Short-term memory has a capacity of about 7 items (Miller 1956) and lasts 20-30 seconds (accepted). Long-term memory has two subtypes: explicit/declarative (including episodic and semantic) and implicit/procedural (critical).

In existing agent surveys, memory is usually treated as one module among many and is rarely analyzed as a first-class system component with a unified interface and lifecycle (accepted). BabyAGI's vector database stores task results as embeddings used for context retrieval (critical), and serves as the agent's memory (critical). BabyAGI uses semantic search to find relevant information in the vector database (critical).

### 4. Agent Evaluation and Benchmarks

Evaluating LLM agents is more complex than evaluating LLMs in isolation because LLM agents operate in dynamic, interactive environments, reason and make plans, execute tools, leverage memory, and collaborate with humans or other agents (critical). LLM agent evaluation differs from traditional software evaluation because LLM agents are inherently probabilistic and behave dynamically, whereas software testing focuses on deterministic and static behavior (critical).

**AgentBench** is a multi-dimensional benchmark consisting of 8 distinct environments to assess LLM-as-Agent's reasoning and decision-making abilities (critical), published at ICLR 2024 (critical, arXiv:2308.03688). AgentBench's extensive test shows that while top commercial LLMs present strong ability as agents, there is a significant disparity in performance between them and many open-source competitors no larger than 70B (critical). AgentBench identifies poor long-term reasoning, decision-making, and instruction following as main obstacles for developing usable LLM agents (critical).

**WebArena** is a benchmark for agents interacting with web environments, including general web navigation (critical). **SWE-bench** is a benchmark for resolving GitHub issues in coding and software engineering tasks (critical). **Tau-bench** evaluates customer service and retail agents in realistic multi-turn settings with simulated users (critical). **VisualAgentBench** (introduced 2024.08.13) evaluates visual foundation agents with 5 environments spanning Embodied, GUI, and Visual Design (critical).

A survey proposes a two-dimensional taxonomy for LLM agent evaluation organized along evaluation objectives (what to evaluate) and evaluation process (how to evaluate) (critical). The survey highlights enterprise-specific challenges such as role-based access to data, reliability guarantees, dynamic and long-horizon interactions, and compliance, which are often overlooked in current research (critical).

### 5. Industry Guidance and Emerging Standards

OpenAI published a 34-page white paper on AI Agents covering building, evaluating, and deploying AI agents, architectures, tool integration, scaling, agent ops and evaluation frameworks (critical), posted on 19 February 2024 (critical). OpenAI also published 'A practical guide to building agents' offering practical guidance on agent architecture, tooling, and safety considerations (critical).

Anthropic published 'Building Effective AI Agents' covering single-agent designs, multi-agent orchestration, and agentic workflows (critical), available at https://resources.anthropic.com/building-effective-ai-agents (critical). Anthropic's guidance emphasizes simple, composable approaches (critical) and distinguishes between workflows (predefined paths) and agents (self-directed using tools) (accepted).

Google published an 'Agents' Whitepaper providing a broad overview and foundational concepts of agentic systems (critical). Google DeepMind published 'Agents Thinking Fast and Slow: A Talker-Reasoner Architecture' proposing a biologically-inspired dual-system framework (critical), and a paper on a delegation framework for coding agent architecture (critical).

The Model Context Protocol (MCP) originated by Anthropic in late 2024 (critical). MCP servers expose tools, resources, and prompts to MCP clients (accepted). OpenAI, Google, Anthropic, and major frameworks all support MCP (accepted).

### 6. Planning Approaches

Planning, which requires strong reasoning abilities, commonly falls into one of five major approaches: task decomposition, multi-plan selection, external module-aided planning, reflection and refinement, and memory-augmented planning (critical). Chain of Thought (CoT) is a standard prompting technique for decomposing hard tasks into smaller steps (critical). Tree of Thoughts (ToT) extends CoT by exploring multiple reasoning possibilities at each step (critical). Task decomposition can be done by LLM prompting, task-specific instructions, or human inputs (critical). LLM+P uses an external classical planner with PDDL for long-horizon planning (critical).

ReWOO (Reasoning Without Observation) plans once with placeholders, runs all tools in parallel, and synthesizes at the end, using only 2 LLM calls total (critical). ReWOO achieves 5x token efficiency over ReAct (accepted), but breaks if a tool returns something unexpected (accepted).

### 7. Algorithm Distillation and Learning Approaches

Algorithm Distillation (AD) applies the idea of Chain of Hindsight to cross-episode trajectories in reinforcement learning tasks, where an algorithm is encapsulated in a long history-conditioned policy (critical). AD concatenates the learning history of an agent across episodes and feeds it into the model, expecting the next predicted action to lead to better performance than previous trials (critical). The goal of AD is to learn the process of RL instead of training a task-specific policy itself (critical). AD demonstrates in-context RL with performance getting close to RL^2 despite only using offline RL and learns much faster than other baselines (critical). Multi-episodic contexts of 2-4 episodes are necessary to learn a near-optimal in-context RL algorithm (critical).

Chain of Hindsight (CoH) fine-tunes the model to improve outputs based on feedback sequences (critical).
