## Executive Summary

- Communication is a core mechanism for coordinating multi-agent behaviors, broadening environmental views, and supporting collaboration across both multi-agent deep reinforcement learning (MADRL) and LLM-based multi-agent systems.
- MetaGPT is a prominent multi-agent framework that encodes Standard Operating Procedures (SOPs) into prompt sequences, assigns distinct roles (e.g., product manager, engineer, QA), and achieves state-of-the-art results on code generation benchmarks (85.9% and 87.7% Pass@1 on HumanEval and MBPP).
- ReAct (synergizing reasoning and acting) and Reflexion (verbal reinforcement learning) are foundational techniques for LLM agents, with ReAct alternating between thinking and doing for tool-heavy workflows and Reflexion extending ReAct through iterative reflection phases.
- Agent architecture vocabulary stabilized around eight canonical patterns spanning four quadrants (single-agent, collaborative multi-agent, competitive multi-agent, orchestration topology), with most production systems composing two or three patterns.
- Multi-agent systems show significant performance variability: they can boost performance by 81% on parallel tasks but degrade by up to 70% on sequential tasks when misapplied; agent performance also drops 58% between single execution and eight consecutive runs.

## Findings

### Communication and Collaboration in Multi-Agent Systems

Communication is an effective mechanism for coordinating the behaviors of multiple agents, broadening their views of the environment, and supporting their collaborations. In multi-agent deep reinforcement learning (MADRL), agents can improve overall learning performance and achieve collaboration. Multi-agent reinforcement learning focuses on training the behaviors of multiple learning agents that coexist in a shared environment. MARL models such as the Multi-Agent Transformer (MAT) and ACtion dEpendent deep Q-learning (ACE) have significantly improved performance by leveraging sequence modeling. The card game Hanabi is considered a strong medium for testing and developing MARL algorithms due to its cooperative nature, partial observability, limited communication, and remarkable complexity.

In LLM-based multi-agent systems, multiple specialized agents endowed with distinct identities engage in communication and collaboration to achieve task objectives. LLM-based multi-agent systems have been proposed as a pivotal pathway to harness collective intelligence while preserving the specialized characteristics of individual agents. These systems are considered a promising pathway toward realizing general artificial intelligence equivalent to or surpassing human-level intelligence.

### MetaGPT: Role-Based Multi-Agent Framework

MetaGPT is a multi-agent collaborative framework described as "Meta Programming for A Multi-Agent Collaborative Framework," presented at the Twelfth International Conference on Learning Representations (ICLR) in 2024. It is a multi-agent framework that assigns different roles to GPTs to form a collaborative entity for complex tasks. MetaGPT takes a one-line requirement as input and outputs user stories, competitive analysis, requirements, data structures, APIs, and documents. Internally, MetaGPT includes product managers, architects, project managers, and engineers, providing the entire process of a software company along with carefully orchestrated SOPs.

MetaGPT's core philosophy is "Code = SOP(Team)," materializing SOP and applying it to teams composed of LLMs. The framework encodes Standardized Operating Procedures into prompt sequences for streamlined workflows, allowing agents with human-like domain expertise to verify intermediate results and reduce errors. MetaGPT utilizes an assembly line paradigm to assign diverse roles to various agents, efficiently breaking down complex tasks into subtasks involving many agents working together.

In quantitative results from the MetaGPT paper, MetaGPT achieved an average score of 3.9 across tasks including Flappy bird, Tank battle game, 2048 game, Snake game, Brick breaker game, Excel data process, and CRUD manage. AutoGPT, LangChain, and AgentVerse each achieved an average score of 1.0, while ChatDev achieved 2.1. MetaGPT achieves state-of-the-art performance with 85.9% and 87.7% Pass@1 on HumanEval and MBPP benchmarks. MetaGPT introduces an executive feedback mechanism that debugs and executes code during runtime, elevating code generation quality by 5.4% absolute improvement on MBPP. MetaGPT achieves a 100% task completion rate in experimental evaluations.

MetaGPT requires agents to generate structured outputs such as high-quality requirements documents, design artifacts, flowcharts, and interface specifications. The use of intermediate structured outputs significantly increases the success rate of target code generation by maintaining consistency in communication and minimizing ambiguities and errors during collaboration. MetaGPT reduces the risk of hallucinations caused by idle chatter between LLMs, particularly in role-playing frameworks.

MetaGPT requires Python 3.9 or later but less than 3.12. It can be used at CLI, for example "metagpt "Create a 2048 game"" will create a repo in ./workspace. MetaGPT includes a Data Interpreter role that can write code, such as running data analysis on the sklearn Iris dataset including a plot. MetaGPT is licensed under the MIT license and has 69.8k stars on GitHub.

MetaGPT lacks a visual builder or no-code editor, limiting accessibility for non-technical users. MetaGPT's focus on replicating software development team structures may make it less flexible for applications outside this domain. MetaGPT's strength lies in its ability to handle complex, collaborative coding tasks.

### ReAct and Reflexion: Reasoning and Acting Paradigms

ReAct (REACT: SYNERGIZING REASONING AND ACTING IN LANGUAGE MODELS) was presented at the 11th International Conference on Learning Representations, ICLR 2023, in Kigali, Rwanda. ReAct was authored by Yao, Shunyu; Zhao, Jeffrey; Yu, Dian et al. ReAct alternates between thinking and doing and works well for tool-heavy workflows with well-defined task domains. ReAct tends to struggle when goals span multiple domains and requests get complicated.

ReAct research indicates that large language models perform well on language understanding and interactive decision-making tasks, but their reasoning capabilities (such as chain-of-thought prompting) and action capabilities (such as action plan generation) were previously studied primarily as two independent topics. The core motivation of the ReAct paper is to synergistically combine reasoning and acting.

Reflexion: Language Agents with Verbal Reinforcement Learning (Shinn et al., 2023) was published at NeurIPS 2023, arXiv:2303.11366. The Reflexion pattern extends ReAct through five phases: reasoning, acting, observing, reflecting, and repeating the cycle with learned improvements. ReAct and Reflexion utilize chain-of-thought prompts to generate reasoning trajectories and action plans with LLMs, demonstrating the effectiveness of the ReAct style loop of reasoning as a design paradigm for empowering automatic programming.

Reflection lets agents critique their own outputs and refine iteratively. Reflection-based agent architectures let language agents significantly improve problem-solving performance through iterative refinement, though they cost typically 2-3x more tokens versus single-pass approaches. Self-Refine improves outputs via iterative self-feedback, using the same LLM as generator, refiner, and feedback provider.

### Agent Architecture Patterns and Frameworks

Agent architecture vocabulary stabilized in 2024-2026 around eight canonical patterns. The eight canonical agent architecture patterns span four quadrants: single-agent, collaborative multi-agent, competitive multi-agent, and orchestration topology. Most production agent systems are compositions of two or three patterns from across the four quadrants.

Planning agents split strategy from execution, with the planner creating a complete plan upfront and an executor running each step. Single-query planning is faster but brittle; iterative replanning adapts but costs more. In the orchestrator-worker pattern, an orchestrator agent receives tasks and routes them to specialized worker agents. Mixture of Agents (MoA) architectures exemplify the layered orchestrator-worker approach. A supervisor agent manages multiple specialized agents through tool-based handoffs.

LangGraph is LangChain's graph orchestration framework, strong on graph pattern by design, and supports ReAct, Reflexion, and plan-and-execute via prebuilt patterns. LangGraph implements supervisor routing using state graphs, where nodes represent agent actions and edges define routing logic. LangGraph is an experimental framework that uses graph structures to represent state and context in dialogues with LLMs, supporting cyclical workflows that allow agents to exchange data through a shared knowledge graph, iteratively search for information, assess reliability, and correct responses.

LangChain is a Python agent framework with over 1,000 model and tool integrations. LangChain has the highest download volume among the frameworks compared in the Speakeasy comparison. The October 2025 v1.0 general availability release of LangChain added a simplified create_agent primitive, semantic versioning, and a middleware layer for summarization, PII detection, and human-in-the-loop patterns. LangChain is one of the most popular frameworks for building AI agents that can reason and chain multiple actions together. LangChain is flexible, modular, and integrates easily with LLMs like GPT or Claude. LangChain is an open-source framework that offers developers a comprehensive toolkit for building, deploying, and managing LLM-driven solutions across various domains. LangChain provides modular components including prompt templates, LLM wrappers, and memory systems for maintaining context in conversations. LangChain's retrieval-augmented generation (RAG) capabilities allow developers to enhance LLM responses with external data sources, improving accuracy and relevance. LangChain offers robust support for creating AI agents capable of reasoning and taking actions. LangChain supports a wide array of LLMs, vector stores, and external tools, allowing for customized solutions tailored to specific use cases. LangChain presents a learning curve for newcomers, and its extensive feature set can be overwhelming.

CrewAI, AutoGPT, and Make AI Agents are three frameworks that lead the space for business applications. CrewAI allows you to create multiple agents that collaborate, taking a different approach from LangChain. CrewAI provides a memory system with four core components (short-term, long-term, entity, and external memory) that combine into contextual memory. CrewAI implements the AI-Based Agents Workflow (AgWf) concept, where agents execute steps described as text instructions and can use external tools (Python classes/functions), enabling automation of complex analytical scenarios by combining LLM flexibility with deterministic code.

AutoGen: Enabling Next-Gen LLM Applications via Multi-Agent Conversation was published at the First Conference on Language Modeling (COLM 2024), arXiv:2308.08155, and includes sections on human-in-the-loop agent patterns and UserProxyAgent design. AutoGen is a versatile and customizable framework from Microsoft researchers, designed for creating complex applications based on multi-LLM communication, allowing agent interaction logic to be programmed using both code and natural language, and supporting integration with external tools and APIs.

AgentVerse is an open platform developed by the OpenBMB community for studying dynamic collaboration and emergent agent behaviors, providing two modes: task-solving and simulation. AgentVerse is available on GitHub under OpenBMB/AgentVerse.

BabyAGI's code fits into one Python file with 468 lines of code. BabyAGI acts on a list of tasks and then tries to prioritize them, while AutoGPT tries to act with one task at a time. In BabyAGI, everything is done with an LLM call using GPT-4, and it does not have the ability to use the internet. BabyAGI is an AI-powered task management system with multiple LLM-based agents, where one agent creates new tasks based on the previous task's objective and result, another agent prioritizes the task list, and another agent completes tasks. BabyAGI is a multi-agent system with a fixed order of agents.

CAMEL (Communicative Agents for "Mind" Exploration of Large Language Model Society) focuses on autonomous interaction of agents through dialogue, using an inception prompting technique to coordinate conversations between LLM agents, guiding them toward a common goal.

### Multi-Agent System Performance and Challenges

Multi-agent systems can boost performance 81% on parallel tasks, or tank it by up to 70% on sequential tasks if you pick wrong. Agent performance drops from 60% to 25% between single execution and eight consecutive runs, a 58% degradation.

Multi-agent systems face challenges including hallucinations and cascading errors, scalability and resource intensity, coordination and management, and lack of widely accepted benchmarks for evaluation. In multi-agent systems, an error made by one agent can be passed down the chain to others, who then use it as the basis for their reasoning, leading to skewed results for the entire group (hallucinations and cascading errors). In approaches like Guided Debate or Self-Refine, one agent proposes a solution, while another evaluates and corrects it, which helps reduce errors.

LLM-based agents face the challenges of "assistant repeated instruction" or "infinite loop of message."

### Agent Architecture Vocabulary and Production Patterns

Production systems typically combine planning, tool use, multi-agent coordination, and reflection. Production agents need three types of state: execution checkpoints for resuming after failures, vector storage for semantic search across past interactions, and in-memory coordination for real-time messaging between agents.

Human-in-the-loop (HITL) architectures add human oversight at important decision points, and LangGraph provides built-in interrupts, approval gates, review checkpoints, and feedback loops.

The Model Context Protocol (MCP) standardizes how AI apps connect to external context and tools via MCP servers, though the protocol is still evolving with ongoing work on async operations and production scaling. Anthropic's biggest strategic move in the agent space is the Model Context Protocol (MCP), released in late 2024 as an open standard. MCP defines how AI agents connect to external tools and data sources. With MCP, developers write an MCP server once and any MCP-compatible agent can use it, functioning as a universal connector for agentic systems. OpenAI released a structured Agents SDK.

Frameworks like CrewAI and AutoGen define explicit integration patterns alongside MCP, handling environment-specific restrictions, approval policies, and access controls.

When Anthropic's team optimized their agent for SWE-bench in 2024, they spent more time on tool definitions than prompts. Tool specification matters more than prompt engineering for production agents.

Anthropic's advanced research system uses a clearly defined multi-agent architecture with a lead agent that orchestrates several sub-agents running in parallel. In Anthropic's multi-agent architecture, each sub-agent is asked to explore a specific part of the problem space. For complex topics, Anthropic's design allows Claude to divide the subject into multiple angles and explore them at the same time, then bring the results back to the orchestrator for synthesis.

The survey was received 15 July 2024, revised 21 August 2024, accepted 28 August 2024, and published 08 October 2024.

The survey synthesizes a general structure of LLM-based multi-agent systems encompassing five key components: profile, perception, self-action, mutual interaction, and evolution. The survey illuminates the extensive applications of LLM-based MAS in two principal areas: problem-solving and world simulation. The survey organizes the field of LLM-based multi-agent systems around three key aspects: construction, application, and discussion.

The unified agent framework comprises five essential modules: Profile, Perception, Self-Action, Mutual interaction, and Evolution. LLM-based multi-agent systems (LLM-MAS) workflow encompasses the sequential steps of agent creation, perception, self-action, mutual interaction, and evolution. In a multi-agent system, the initial step involves the creation of profiles that endow each agent with personalized characteristics and subtask allocations. Agents in a multi-agent system engage in evolution, which involves the ongoing reflection on their decisions and actions. The execution of tasks in a multi-agent system relies on the interactions among agents, which collectively contribute to the planning and implementation of the overall mission.

LLM-based agents have made significant strides in interacting with complex environments and solving intricate tasks across a wide range of applications. An increasing number of research studies employ LLM-based multi-agent systems to tackle a variety of complex tasks, such as industrial engineering, scientific experimentation, embodied agents, gaming, and societal simulation.

### Multi-Agent Systems: Definitions and Characteristics

Multi-agent systems (MAS) are complex systems composed of multiple interacting intelligent agents, capable of simulating social interactions and teamwork in the real world. The core advantage of MAS lies in its distributed decision-making and problem-solving capabilities. In MAS, each agent possesses a degree of autonomy, capable of independently perceiving the environment and making decisions. Agents in MAS can interact with other agents by simulating real-world collaboration patterns such as cooperation, competition, and hierarchical organization.

Reinforcement learning (RL), as a core MAS technology, allows agents to learn optimal behavioral strategies through interaction with the environment. Marllib distinguishes MARL algorithms based on four dimensions: task patterns, agent types, learning styles, and knowledge sharing. MAS is divided into agent-level and system-level characteristics. Four different MAS prototypes were summarized based on the dimensions of agent heterogeneity and communication.

A single-agent system consists of a single LLM-based intelligent agent capable of independently perceiving its environment and making decisions. The core of a single-agent system lies in the individual characteristics, perception abilities, and self-action capabilities of the agent. A notable advantage of single-agent systems lies in their focus and efficiency, as centralized processing reduces the need for resource allocation among multiple agents. Compared to multi-agent systems, the design and maintenance of single-agent systems are simpler and more straightforward, as they do not require complex communication and coordination mechanisms.

### Trust Scoring and Agent Evaluation

ReliabilityBench is a benchmark for evaluating LLM agent reliability across three dimensions, including consistency under repeated execution.

Cleanlab's study evaluates 5 AI Agent architectures over the BOLAA (ICLR 2024) benchmark. Trust scoring automatically reduces incorrect responses across all AI Agent types: from Act by 56.2%, from ReAct (Zero-shot) by 55.8%, from ReAct (Few-shot) by 15.7%, from PlanAct by 24.5%, and from PlanReAct by 10.0%.

The BOLAA benchmark's underlying dataset (HotPotQA) includes single- and multi-hop questions that require reasoning across multiple data sources for the Agent to produce the correct answer. The Act Agent directly generates actions and then a final response using only the task instructions (no intermediate reasoning steps nor few-shot examples), and is referred to as Zeroshot in the BOLAA paper. ReAct (Zero-shot) adds a "think" step (chain-of-thought reasoning) before each step where the Agent chooses an action, but without any few-shot example trajectories in the prompt; it is referred to as ZeroshotThink in the BOLAA paper. A standard ReAct Agent includes few-shot example trajectories in its prompt in addition to utilizing chain-of-thought reasoning, and is a common type of AI Agent used today as it is quite general. PlanAct is a Plan-then-Act Agent that generates a full plan before executing any actions, rather than reasoning in every step, and has few-shot examples in its prompt. PlanReAct combines planning and chain-of-thought reasoning, has few-shot examples in its prompt, first generates a plan and then uses the ReAct framework to execute on that plan.

In the benchmark, each Agent response was categorized as Correct, Incorrect, or Not Attempted, and responses with TLM trust score below a 0.8 score threshold were treated as Not Attempted. Halted = % of tasks where no response was produced because AgentLite exceeded its 10-step limit. To grade Agent responses, the study relies on the ground-truth answers available in the BOLAA benchmark and uses OpenAI's SimpleQA LLM-grading templates to evaluate Agent responses against ground-truth answers.

### Tool Use in LLM-Based Agents

Tool use includes tool selection, tool calling, and other directions. Tool selection includes external retrievers, multi-label classification, and vocabulary-based retrieval methods. External retrievers include AnyTool, ProTIP, and Toolshed. Tool calling includes in-place parameter filling and parallel tool calling methods. In-place parameter filling includes Toolformer and Chain-of-Abstraction. Parallel tool calling includes CATP-LLM and LLM-Tool Compiler.

Tool use categories include tool selection (external retrievers, multi-label classification, vocabulary-based retrieval), tool calling (in-place parameter filling, parallel tool calling, cost-aware tool calling, efficient test-time scaling, efficient tool calling through post-training), and tool-integrated reasoning (selective calling, cost-aware policy optimization).

### Planning in LLM-Based Agents

Planning categories include single-Agent planning efficiency (adaptive budget and control, structured search, task decomposition, policy optimization, memory and skill acquisition) and multi-Agent collaboration efficiency (topology efficiency and sparsification, protocol and context optimization, distilling coordination into planning).

### Industry Adoption and Market Data

According to Gartner's October 2024 Hype Cycle report, 33 percent of enterprise software will include agentic AI by 2028, up from less than 1 percent in 2024. According to a September 2024 Anthropic research post on multi-agent systems, task specialization reduces error rates by 40 percent.

Customer shopping assistants use ReAct for real-time personalized experiences, accepting higher token costs for dynamic adaptation. Inventory systems use Plan-and-Execute for supply chain coordination, benefiting from predictable sequences and lower costs. A ReAct agent handling customer support queries might make 5-7 LLM calls per interaction as it reasons and acts in loops. A planning pattern for the same task often cuts this to 3-4 calls total—1 for planning, then execution—because it creates the complete plan upfront.

Financial services institutions deploy parallel multi-agent patterns where specialized agents simultaneously process independent risk factors, with unified risk decisions synthesized across agent outputs. Financial services uses multiple multi-agent coordination approaches for regulatory compliance, including workflow patterns, swarm patterns for distributed reasoning, and graph patterns (hierarchical structures), supplemented by iterative loop patterns for refinement. Healthcare is deploying hierarchical agent systems for ambient documentation, prior authorization, and patient monitoring, though human-in-the-loop oversight remains a requirement for regulated workflows.

Teams with solid evaluation infrastructure can upgrade models in days, while those without evaluation systems often face weeks of manual testing.

A general-purpose consumer AI provider like OpenAI is incentivized for their AI to seem extremely helpful, which is why hallucinated/incorrect responses are common from their API.

Trust scoring allows achieving a 5% error rate requirement without sacrificing the helpfulness of the AI Agent too severely. Trust scoring is best for use-cases where you need to tightly control AI Agent error rates. If you want an AI Agent that feels helpful no matter what (never abstains from answering) even if it gets many answers wrong, trust scoring is probably not applicable. A trust score threshold of 0.8 was used as an example in the benchmark, but the optimal threshold value depends on the use-case. Cleanlab's benchmark reveals that trust score guardrailing significantly reduces incorrect responses across all Agents.
